# Code signing, and how to check a download instead

## Current status

Releases are **not code-signed**. Windows SmartScreen warns that the publisher is
unknown; choose **More info -> Run anyway** to install.

Signing through the [SignPath Foundation](https://signpath.org), which provides
certificates to open-source projects, was applied for on 2026-09-17 and declined on
2026-09-18. No certificate is in place and none is currently being pursued: a
certificate that would clear the SmartScreen warning outright costs a few hundred euro
a year, which is not a sensible trade for a project at this size. That may change; this
file will say so when it does.

The release workflow still contains the signing steps. They are gated on a
`SIGNPATH_API_TOKEN` secret that does not exist, so they are skipped and every release
is published unsigned. Nothing about a tag build depends on them.

## Verifying a download

Every release publishes `SHA256SUMS.txt` alongside the installers, and the same values
are printed in the release notes. After downloading, compare:

```powershell
Get-FileHash .\NOBS.SQL.Editor_1.3.4_x64-setup.exe -Algorithm SHA256
```

The hash it prints should match the line for that file. The checksums are generated by
the release workflow from the artifacts it just built, and published in the same run -
so they establish that your download arrived intact and matches what CI produced from
this repository. They are not a signature, and cannot be: anyone who could replace the
installer on the release page could replace the checksum file with it. What they do
catch is a truncated or corrupted download, and a file that came from somewhere other
than the release page.

The stronger check, if you want one, is to build from source (see the README) and
compare that against the published installer, or simply run your own build.

## What would be signed, if signing is ever in place
- Windows installer packages (`.exe` / `.msi`) published on GitHub Releases.

## Build process
- Artifacts are built from this repository using GitHub Actions CI.
- Only CI-built artifacts are published; releases are never built on a developer machine.
- No signing key exists for this project, and none is stored anywhere. If signing is set
  up later through a service that holds the key (SignPath and Azure Trusted Signing both
  do), this project will still not hold it.

## Privacy
This application does not transmit user data to the author, and has no
telemetry. Database credentials are stored locally (OS keychain / local
config), and database connections go only to the servers the user configures.

Apart from those, the application makes these network requests:
- **Update check:** a few seconds after start, a request to the GitHub API
  (`api.github.com`) for the latest release of this project, to show a notice
  when a newer version exists. It sends nothing beyond the request itself, and
  can be switched off under Settings -> Updates.
- **Client tools download,** only when the user clicks the button in Settings:
  - the MariaDB client tools, from mariadb.org (`downloads.mariadb.org` and
    `mirror.mariadb.org`);
  - the MySQL client tools, from dev.mysql.com (`dev.mysql.com` and
    `cdn.mysql.com`, or `downloads.mysql.com` for older releases).

  Both archives are checked against the checksum their publisher provides before
  anything is unpacked, and a download that cannot be checked is not installed.

The release page (github.com) and the author's donation page open in the
user's browser only when the user clicks them.
